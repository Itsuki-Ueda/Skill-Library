# 道具を作る

手で済ませるには多い作業や、あとで確かめ直しが要る作業は、手で直さずに、それをする道具（一括書き換えのスクリプト・生成・集計・検査）を作って流す。

## なぜ

道具は毎回同じようにやり、何度でも流し直せる。レビューする人は道具を読んで流せば確かめられる。手作業の変更は、やり直さないと確かめられない。

## やり方

- 一目で分かる2〜3か所の編集なら手でよい。それ以外は道具を作るのを既定にする。
- 最初の1件は手でやって手順を覚え、それから道具にする。その1件に道具を流し、手でやった結果と差分が無いことを確かめる。道具は流し直しても安全にする（何度流しても安全に）。
- 道具で一度に全部処理できるなら、自分で流す。道具で済む作業をサブエージェントに手分けさせない。
- 手分けするなら、手順・確かめ方・触ってはいけない範囲を1つの文書（契約）にまとめ、全員がそれを読む。
- 作るのは仕事を済ませる最小のスクリプトにする。枠組みは作らない。
- セッションの後も使うなら、道具をコミットする。

## 飛ばしたと分かる印

この原則に従ったと言うのに、差分にスクリプト・生成・検査のどれも無い。
