# 試せば分かることは聞かない

人間は非同期に見ている。元に戻せる作業なら、もっともな判断をして進め、結果を見せる。人間に聞くのは、試しても分からないことと、元に戻せないことだけにする。

## なぜ

コードの変更は元に戻せて、レビューもできる。間違った判断の手戻りは、たいてい人間を待つ時間より安い。

## やり方

- 聞く前に仕分ける。
  - 試せば分かる（小さな実験・試作・計測で決まる）なら、試して決める。
  - 元に戻せる実装上の選択なら、決めて進み、理由を報告に書く。
  - 元に戻せない操作（force push・本番データの削除・外への送信）、製品の方向・要求そのもの・お金や権限に関わることは、聞く。
- 「X してよいか」と聞かずに、X をして、なぜそうしたかを示す。
- 問題に気づいたら記録し、次の回で直す。

## 守ること

決められた確認（agent-team の[3]の計画承認、契約の前提を変えるときの NEED-DECISION など）は、この原則で省かない。この原則は聞かなくてよいことを聞かないためのもので、決められた確認を飛ばす理由にはならない。
