# 数字の出どころを説明する

報告に数字（速度・件数・割合・減った量）を書くときは、その数字を決めているものと、別のものを測っていないことを示す。

## なぜ

数字は、それらしく見えても、エラーやキャッシュや動いていないコードを測っていることがある。出どころを言えない数字は、何を測ったのか分かっていない。

## やり方

- 「なぜ2倍ではないのか」を問う。上限を決めているもの（CPU・ロック・ディスク・ネットワーク・負荷をかける側）を、実行中の計測から名指しする。コードを読んだだけの推測は上限の説明にならない。
- 数字が実は別のものを測っている可能性を挙げ、1つずつ証拠で外す。よくあるのは、エラー、飛ばされた処理やキャッシュ、実行されなかったコード、片側だけ調整していない比較、ばらつき、全体から見て小さすぎる部分。
- 数字と一緒に、回数・ばらつき・上限を決めているものを残す。
- 件数・回数・時間は、記録（git log・ログ・ファイル）で数え直してから確定値として書く。数え直していない値は「自己申告」と書く。

## 飛ばしたと分かる印

数字に、回数もばらつきも上限の名前も付いていない。または、縮んだ時間が、変えた部分にもともとかかっていた時間より大きい。
