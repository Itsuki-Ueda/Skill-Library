# 共有しない

同時に動くもの（並列のワーカー・レーン・プロセス）が同じ書き込み先を使いそうなら、まず共有をやめられないかを考える。本当に共有が要るときだけ、順番を仕組みで守る。

## なぜ

同じものへ同時に書くと、たまにしか起きず、再現しにくく、調べるのが高くつく競合が起きる。

## やり方

1. 共有している書き込み先を挙げる（両方が読み書きするファイル、両方が push するブランチ、両方が定義して使う API）。
2. 既定は、書き込み先を分けること。それぞれが自分のファイル・キー・ブランチ・作業ツリーを持ち、読む側か報告の段階でだけまとめる。1つの `state.json` にそれぞれが自分の欄を書くのは、まだ共有している。
3. 1つの書き込み先が本当に必要なときだけ、順番を仕組みで守る（ロックファイル・工程を分ける・書き手を1人にする）。「気をつける」という決まりは仕組みではない。

## 飛ばしたと分かる印

並列の計画に「同じファイルを触るが、ぶつからないよう注意する」と書いてある。
