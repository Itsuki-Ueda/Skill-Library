# reflect — 振り返りから改善案を作る

今の会話から、次の作業でも効く学びを取り出し、行き先に振り分ける。1回きりの出来事は学びに数えない。
会話が短い、作業と関係ない、使ったスキルどおりに問題なく進んだ、のどれかなら、やらずにそう伝える。

## 1. 会話の記録を探す

- Claude Code: `~/.claude/projects/<作業フォルダの名前を変換したもの>/` の新しい `*.jsonl`。サブエージェントの記録は `<会話ID>/subagents/*.jsonl`。
- Codex: `~/.codex/sessions/` の新しい rollout。
- 候補の先頭の数行を読み、この会話の最初の依頼と一致するものを使う。今の作業フォルダ以外の記録は読まない（関係ない会話を読まないため）。
- 見つからなければ、会話の要約（依頼、判断、受けた指摘、やり直した点）を自分で書いて代わりに渡す。

## 2. 3つの観点で同時に読む

1つのメッセージで3人を同時に起動する。依頼文は `references/lenses.md` の各観点をそのまま使い、記録のパスを差し込む。

| 観点 | 担当 | 見るもの |
| --- | --- | --- |
| 判断 | カスタム Agent `reflect-lens`（Sonnet・effort high） | 間違い、受けた指摘、人間の好み、判断の理由 |
| 道具 | カスタム Agent `reflect-lens` に `model: haiku`（Haiku・effort high） | コマンド・設定・環境の罠、人間が手で渡した情報 |
| 別の見方 | カスタム Agent `reflect-lens`（Sonnet・effort high） | 理由を取り違えたままうまくいった判断、飛ばした確認、見落とした波及 |

- 2026-10-18 の比較（同じ記録2本）で、Opus 2人と Codex の組み合わせと同じ大事な提案が残り、費用は約3分の1になった。Sonnet medium は1本で大事な提案を2件落とした。
- Codex のセッションで頼まれたときは、3つの観点をカスタム Agent `researcher` で回す。
- 返答は親が受け取る。読み取り専用の担当にファイルの保存を求めない。

## 3. まとめる

3人の返答を `references/lenses.md` の「まとめ役」の依頼文に差し込み、Agent（汎用、model: opus）に渡す。Codex のセッションでは、まとめ役もカスタム Agent `researcher` に渡す。返ってくるのは「採用・却下・保留」の表。
採用の各行は、次のどれかの行き先を持つ。

| 行き先 | 何を | どう反映するか |
| --- | --- | --- |
| プロジェクトの教訓 | このリポジトリだけの罠、人間の好み | memory-ops の入口（INBOX に1行。同じ主題の2回目で正式な記憶へ） |
| プロジェクトの確認手順 | このアプリだけの動かし方・確かめ方（コマンド、テスト用のデータ、画面の操作） | verify-ops の手順で、プロジェクトの `.agents/skills/verify/` の編集案を作る（verify が無ければプロジェクトの教訓へ） |
| スキルの改善 | 使ったスキルの穴、発火すべきだったのにしなかった説明文。ほかのプロジェクトでも同じ形で起きるものだけ | skill-ops の手順で編集案を作る |
| 仕組みで止める | lint・スクリプト・型・CI・テストで機械的に止められるもの | 下の4の順で対策案を作る |

## 4. 仕組みで止める

同じ指摘を2回受けたものは、文章を足す前に、上から順に止められる形を探す。

1. 作りで無くす。状態の持ち主を1つにする、やり方を1つにする、古いやり方を消す。
2. 型で書けなくする。書けてしまうなら、直し方を名指しするエラーを出す lint や CI の検査を足す。
3. 振る舞いのテストにする。
4. 最後に文書やルール。文書は飛ばしても何も止まらないので、判断が要るものだけにする。

新しい検査は、過去に実際に起きた間違いで落ちることを確かめてから入れる。

## 5. 行き先ごとに渡す

スキルはこの先のすべての作業に効くので、このセッションでは反映しない。採否は人間が1か所でまとめて決める。

| 行き先 | 渡し方 |
| --- | --- |
| プロジェクトの教訓 | 聞かずに memory-ops の入口（INBOX）へ書く。正式な記憶になるのは2回目なので、そこで止まる |
| プロジェクトの確認手順 | 編集案を人間に見せ、承認された分だけ verify-ops で反映する |
| スキルの改善・仕組みで止める | `references/issue.md` の手順で、判断待ちのイシューを3件まで立て、残りは候補のイシュー1件にまとめる |

- イシューの出す先は `~/.config/skill-library/reflection-repo`（1行の `owner/repo`）から読む。リポジトリに書かないのは、出す先が非公開のリポジトリで、名前をここに書けないため。
- 出す先が読めない、または `gh` で出せないときは、今までどおり表を人間に見せ、承認された行だけ skill-ops で反映する。
- 人間への報告は文書ルール（`~/.agents/docs/writing-policy.md`）に従う。

## 6. 報告

- イシュー: 判断待ちと候補の各リンク。「2回目」として既存のイシューに足したもの・候補から上げたものはそのリンク。
- INBOX に入れたもの: 1行ずつ。
- 却下: 理由と一緒に1行ずつ。
