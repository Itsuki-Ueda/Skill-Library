# 作業の型: 画面

中身は UI 規約（プロジェクトにあればそれ、無ければ `~/.agents/docs/ui-policy.md`）にあり、この型は規約の原則12「進め方」を工程に割り当てるだけ。
この型は、自分の見出しにある段の中身を決める。見出しの無い段は共通本体どおりに進める。

## [2] 調査の問い

- 同じ意味のものを、ほかの画面でどう表しているか（規約の原則5。差分の外の画面も探す）。
- 最悪の条件（最小の幅・最大の件数・最長の文字）で、今の画面はどうなるか（原則2）。

## [3] 契約の既定欄

- 見た目・文言・配置を新しく決めるなら、規約の原則12のとおり状態ごとの動くモックを複数作って計画の承認の材料に入れ、選ばれたモックを契約の「モック」欄に書く。
- 契約の「画面確認」欄を埋める（dispatch「画面確認（前倒し）」）。確かめる操作（修飾キー付きの操作、ボタンにフォーカスがあるときのキー、保存中・読み込み中の戻る・閉じる・キャンセル）は、当てはまらないものも「該当なし: 理由」と書く。
- 足す操作・設定・表示のそれぞれに理由を書く。理由を書けないものは足さない。

## [6] 検証

- 仕上がりを撮影してモックと並べ、違いを確かめる（規約の確かめ方にある状態も、撮れる範囲で撮る）。

## [8] 報告

モックとの違いと、モックで決まっていなかった見た目を規約のどの原則で決めたかを、完了報告の骨組みの2に入れる。
