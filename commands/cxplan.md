# /cxplan — Codex プランレビューゲート（自動ループ）

指定した**プラン文書**を Codex にレビューさせ、合格ライン（**P2まで全クリア**）に達するまで
「**Claude が修正 → 再レビュー**」を自動で回す。差分でなく文書が対象な点が `/cxloop` との違い。
このスキルは**引数解決・手順・合否判定・ループ・報告**に専念する。Codex 呼び出しの構文はプロトコルに従う。

## 0. プロトコルを読む（最初に必ず）
- まず `~/.agents/docs/codex-protocol.md` を Read する。
- 以降の Codex 呼び出しはすべてそのプロトコル（`-c` 固定 / stdin / `-o` / session id / timeout / 失敗時 / 履歴）に従う。

## 前提（最初に1度だけ確認）
- `codex --version` が通る。`~/.codex/auth.json` が存在（`codex login` 済み）。無ければ停止して報告。
- 引数のプラン文書が存在すること（絶対パスに解決）。

## 引数（`$ARGUMENTS`）
- `<plan文書のパス>`（必須）→ レビュー対象（例 `tasks/autodev/foo.md`）
- `model <name>` → モデル上書き（既定はプロトコル §1）
- `effort <level>` → **未指定時は段階制（値はプロトコル §1）。指定時は全ラウンドその値で固定。**
- `max <N>` → **再レビューの上限回数**（初回レビューは含まない。既定 3 ＝計最大 4 回のレビュー）

## 手順

1. **前提チェック**（上記＋プロトコル Read）。NG なら理由を述べて終了。
   引数から plan path（絶対パス化）・model・effort・max を解決。出力用ファイル `<out>`（scratchpad）を決める。

2. **初回レビュー**（プロトコルの**文書レビュー形**、初回 effort＝プロトコル §1）。
   プロンプトは**プロトコルの雛形 8a** を使う（`<abs path>` = plan の絶対パス）。
   - session id を標準出力ヘッダから記録、指摘は `<out>` から読む。

3. **合否判定**：
   - `[P0]`/`[P1]`/`[P2]` が **1件でもあれば → 要修正**。
   - 残りが `[P3]` のみ、または指摘なし → **合格**。

4. **合格なら**：手順 7 へ。残っている `[P3]` があれば列挙する。

5. **要修正なら**：各 `[P0]/[P1]/[P2]` に従って **Claude がプラン文書を修正**（Edit/Write）。
   `[P3]` はついでに直してよいが任意。何をどう直したか 1 行ずつ記録。**プラン文書以外は触らない**。

6. **再レビュー**（プロトコルの**再レビュー形**＝resume、effort＝プロトコル §1 の再レビュー値。雛形はプロトコル 8b）。
   `<out>` から結論を読み、新しい指摘・残課題を抽出 → **手順 3 に戻る**。
   `max` 回の再レビューで合格しなければ **未解決の指摘を添えて人間にエスカレーション**して終了。

7. **最終報告**：model / effort（ラウンド別）/ session id / ラウンド数 / 最終判定（合格 or エスカレーション）/
   各ラウンドの指摘と対処 / 残した `[P3]`。session id は必ず示す（後から `codex resume <id>` で辿れるように）。

## 注意
- レビューは Codex に**プラン文書を読ませて**行い、**修正は Claude 側**で行う（Codex に書かせない）。
- これは**プラン（設計）の妥当性ゲート**。コード差分のレビューは `/cxloop` を使う。
