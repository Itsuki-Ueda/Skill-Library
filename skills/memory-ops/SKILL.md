# /memory-ops — プロジェクト記憶の管理

プロジェクトの記憶を「増えすぎない・古くならない・二重に書かない」状態に保つ。
**agent-team のワークフローには依存しない**。記憶ファイルに書く・読むすべてのセッション
（素の CC、Codex、autodev、handoff、agent-team）がこの規約に従う。
agent-team は「いつ測るか・超えたら本スキルを呼ぶ」だけを持ち、規約の正本はここ。

## 原則

1. **測ってから動く**。行数は `scripts/check-size.sh` で測る（目視や記憶で判断しない）。
2. **閾値超過は放置しない**。agent-team 起動時は作業前に実施。それ以外のセッションでは
   着手前に人間へ一言告げ、実施するかは人間が決める（git 履歴に残るので消しても失われない）。
3. **1回目・2回目は候補、3回目で正式**。人間が「覚えて」と明示したものだけ直行。
4. **根拠のない記憶は残さない**。file:line か日付付きの実測が無い項目は refresh で落とす。
5. **同じ主題を2か所に書かない**。書き先は「誰が読む必要があるか」で1つに決める。

## 記憶ファイルと役割

| ファイル | 何を書くか | 誰が読む | いつ読まれる | 上限 |
| --- | --- | --- | --- | --- |
| リポジトリ `AGENTS.md` | コードを壊さないための規約（ビルドの癖・配置・検証コマンド・DB制約）と、**人間の決定・好み**（プロジェクト全体に効くもの） | **全員**（Codex はネイティブ、CC は `CLAUDE.md` の `@AGENTS.md` 経由） | 毎セッション・毎タスク自動 | 200行 |
| `.agents/state/MEMORY.md` | **ミッションを回す知見だけ**（分解の癖・レビューが見落とす箇所・dispatch の癖） | agent-team の Orchestrator だけ | agent-team 起動時 | 150行 |
| `.agents/state/STATE.md` | 現在地（進行中ミッション・Blockers・受入負債・直近 Log） | Orchestrator だけ | agent-team 起動時 | 100行 |
| `.agents/state/INBOX.md` | 教訓・罠の候補箱。初出はここ | 書く人全員 / 読むのは棚卸し時 | 起動時には読まない | 60行 |
| CC 自動メモリ（`~/.claude/projects/<project>/memory/`） | Claude がこのユーザーとどう働くか・このPCの道具の癖（プロジェクト非依存） | CC の Claude だけ | CC 起動時 | 本スキルの管理外 |

- **全セッション横断の共有記憶は AGENTS.md**。新しい読み込み機構は作らない（ハーネスがすでに読んでいる）。
- STATE.md と MEMORY.md は agent-team のワークフロー状態なので、agent-team 以外のセッションは読まない。
  それで困る内容（人間の決定・好み等）があれば、それは置き場所が間違っている → AGENTS.md へ。
- 1ミッション限りの経緯はミッションファイル（`.agents/state/missions/`）に残す。記憶ファイルには書かない。

### 書き先の判定（迷ったとき）

1. Orchestrator 以外（ワーカー・素のセッション・人間）が知らないと困るか？ → **Yes: AGENTS.md**
2. No で、agent-team でミッションを回すときだけ効くか？ → **Yes: MEMORY.md**
3. No で、プロジェクトに関係なく Claude の働き方の話か？ → **CC 自動メモリ**（本スキルの管理外）
4. どれでもない → 記憶ではない。ミッションファイルか docs/ か、書かない。

## 記憶の書式（AGENTS.md・MEMORY.md・INBOX.md 共通の必須項目）

```
- [確認 2026-08-05 | 根拠 scripts/compile-api-lib.mjs:29-31] `lib/` にサブディレクトリを作ると .ts のまま残り Vercel で ERR_MODULE_NOT_FOUND
  → 共有コードは `lib/` 直下にフラットに置く。検出: `ls api/lib/**/*.ts` が空であること（詳細: missions/closed/M-006.md）
- [人間指示 2026-09-03] UI 変更は実装前に動くモックを複数出して選ばせる
```

- **本文は「症状・条件 → 対処」の形で書く**。対処が無い罠は「気をつける」以外に使い道が無く、
  次に踏んだ人が同じ調査をやり直す。対処には**回避方法か検出方法**（コマンド・確認手順）を1行で入れる。
- 対処が1行に収まらない場合は要点だけ書き、手順の全文はミッションファイルか docs/ に残して参照で指す。
- `確認 <日付>`: 最後に根拠を照合した日。refresh で更新する。
- `根拠 <file:line | コマンド | 実測日>`: 照合に使える場所。**これが無い項目は refresh で削除対象**。
- `人間指示 <日付>`: 人間が明示的に記憶を指示した項目（決定・好みは通常これ）。
  **refresh は削除せず報告だけ**（消せるのは人間）。
- 1項目は原則3行以内。

AGENTS.md の既存の節構成（Team Worker Rules / Design / 罠 等）は変えなくてよい。
項目単位でこの書式に揃える。

## 閾値と計測

| ファイル | 閾値 | 超えたら |
| --- | --- | --- |
| `AGENTS.md` | 200行 | `refresh` |
| `.agents/state/STATE.md` | 100行 | `distill` |
| `.agents/state/MEMORY.md` | 150行 | `refresh` |
| `.agents/state/INBOX.md` | 60行 | `promote` |

```
bash ~/.agents/skills/memory-ops/scripts/check-size.sh
```

cwd と1階層下から `AGENTS.md` と `.agents/state` を探し、存在するファイルの行数と超過を1行で出す
（`.agents/state` が無いプロジェクトでも AGENTS.md は測る。どちらも無ければ無音）。
SessionStart hook（`~/.claude/settings.json`）から同じスクリプトが `--json` で呼ばれ、
毎セッション冒頭に結果が表示される。

超過表示を見たときの扱い:
- **agent-team 起動時**（status / resume / [0] / [7]）: 作業に入る前に該当サブコマンドを実施する。
- **それ以外のセッション**: 着手前に「超過している。いま整理するか」を人間に一言告げる。
  人間が指示したら実施、指示が無ければ通常の作業を続ける。黙って無視はしない。

## 記録の入口（新しい教訓・罠・決定が出たとき）

1. まず INBOX.md を主題で grep する。**同じ主題があれば回数+1・最終日を更新**（新しい行を足さない）。
   INBOX.md が無ければ `.agents/state/INBOX.md` をテンプレート（下記の表ヘッダ）で作る。
2. 無ければ INBOX.md に1行追加。**初出では AGENTS.md / MEMORY.md に書かない**。
3. 回数が **3** に達したら `promote` で正式記憶へ移す。
4. 人間が「覚えて」「記憶して」「今後は〜すること」と明示した → INBOX を経ず、書き先判定に従って直行。
   `[人間指示 <日付>]` を付ける。
5. CC 自動メモリに属する内容（作業の仕方への feedback 等）は INBOX に入れず、CC のメモリ機構で扱う。

INBOX.md の書式（1件1行の表）:

```
| 初出 | 最終 | 回数 | 症状・条件 | 対処（回避 or 検出） | 根拠・詳細 | 昇格先 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-09-03 | 2026-09-03 | 1 | 求人タイトル提案が取り込み元ファイル名を拾う | 構造行を先に除外してから候補抽出。テスト: ファイル名入り fixture | lib/title.ts:40 / M-021 | AGENTS.md |
```

- 「対処」欄は空にしない。解決していない罠は INBOX ではなく STATE.md の Blockers か BACKLOG に置く
  （候補箱は「次に踏んだら何をするか」が決まっているものの箱）。
- 「根拠・詳細」欄には照合用の file:line と、手順の全文がある場所（ミッション ID や docs/ のパス）を併記する。

## サブコマンド

### `/memory-ops distill` — STATE.md を100行以下に戻す

1. `check-size.sh` で現在値を記録する（報告に前後の行数を書く）。
2. **Log**: 各エントリを1行にする。1行に収まらない内容（原因分析・レビュー経緯・教訓）は、
   先に該当ミッションファイル（`missions/closed/M-xxx.md`）へ移してから削る。
   教訓はミッションファイルではなく「記録の入口」（INBOX）へ。Log に残すのは直近 20 件まで。
3. **規約外の節**（Missions / Blockers / 受入負債 / Log 以外）: 内容を分類して移す。
   設計不変条件・罠 → 記録の入口へ。完了済みミッションの補足 → 削除（git にある）。節ごと消す。
4. **Blockers**: 解消済みは削除。長文はミッションファイルへ移して1行にする。
5. **Missions**: done の残骸行を削除（Log に1行あれば足りる）。
6. **受入負債の表は行数を理由に消さない**（人間が受入するか放棄を宣言するまで残す）。
7. `check-size.sh` で 100 行以下を確認し、コミットする。

### `/memory-ops refresh` — 記憶の根拠を照合して最新化する

対象: **AGENTS.md 全体**（罠節だけでなく Design・検証コマンド・規約も陳腐化する）と `MEMORY.md` 全項目。

1. **根拠の無い項目**を列挙する。根拠を付けられるものは付け、付けられないものは削除候補にする
   （`[人間指示]` は削除候補にせず報告のみ）。
2. **根拠のある項目**を researcher（**sonnet**）に一括で照合させる。30件を超えるなら分割し、結論に効く項目は
   2本のスコープを重ねる。「消滅」は記憶の削除に直結する再現率タスクなので haiku には出さない
   （初回実行で haiku は「行番号が動いただけ」の2件を消滅と誤報した。sonnet は10件中誤報ゼロ）。
   依頼文の必須要素: 「各行の根拠（file:line／コマンド）を開き、記述が今も成立するかを
   **成立／変化／消滅** の3分類で返す。判定の根拠は逐語引用で示す。推測で成立にしない。
   **行番号は目安であり、その行に無ければファイル全体と近い名前を grep してから消滅と言う**。
   消滅には使った検索パターンを列挙する」。
3. 受領した判定は第1.5層の検証プロトコル（CLAUDE.md）で扱う: 「変化」「消滅」は採用前に自分で裏取りする。
4. 反映: 成立 → `確認` 日付を更新。変化 → 内容を書き換え、確認日更新。消滅 → 削除。
5. **重複統合**: 同じ主題が AGENTS.md と MEMORY.md の両方にある → 書き先判定で片方に寄せる
   （ほとんどは AGENTS.md 側に残る）。同じファイル内で同主題が複数行に分かれているものは1項目に統合する。
6. **書式の統一**: 「症状→対処」「確認日・根拠」の無い項目を書式に揃える。
7. `check-size.sh` で AGENTS.md 200行以下・MEMORY.md 150行以下を確認し、コミットする。
   切らない場合は、要点だけ残して詳細を docs/ かミッションファイルへ移す。

### `/memory-ops promote` — INBOX.md を棚卸しして昇格・掃除する

1. 回数 ≥ 3 の行 → 昇格先（AGENTS.md / MEMORY.md）へ書式付きで移し、INBOX から削除する。
2. 初出から **60日** 経過して回数 3 未満のままの行 → 削除する（git にある。再発したら初出扱いで戻る）。
3. 昇格先が空欄の行は書き先判定で埋める。
4. `check-size.sh` で INBOX.md が 60 行以下になったことを確認し、コミットする。

### 引数なし `/memory-ops`

`check-size.sh` を実行し、超過しているファイルに対応するサブコマンドを順に実施する。
超過が無ければ現在値だけ報告して終わる。

## 禁則

- 閾値超過を見て黙って作業に入る（agent-team 起動時は実施、それ以外は人間に告げる）。
- 根拠の無い項目を「たぶん今も正しい」として残す。
- 1回きりの事故を初出で AGENTS.md / MEMORY.md に書く（INBOX を経る）。
- 人間の決定・好みを MEMORY.md に書く（Orchestrator 以外が読めない。AGENTS.md へ）。
- `[人間指示]` の項目を Orchestrator や Claude の判断で削除する。
- STATE.md に Missions / Blockers / 受入負債 / Log 以外の節を作る。
- ワーカー・サブエージェントに記憶ファイルを書かせる（照合は読み取り専用）。
