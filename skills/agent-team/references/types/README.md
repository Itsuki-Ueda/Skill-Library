# 作業の型の選び方

型は、作業の種類ごとの手順書。各型は自分の見出しにある段の中身を決め、見出しの無い段は共通本体どおりに進める。

## 選び方: 依頼の呼び方ではなく、作業の中身で選ぶ

当てはまるものを全部選ぶ（1つに絞らない）。

| 作業の中身にこれがあれば | 型 |
| --- | --- |
| 期待と違う動き・エラー・データの誤りを直す | `bug-fix.md` |
| 新しい振る舞い（できること）が増える | `feature.md` |
| 振る舞いを変えずに、作りだけを変える | `refactor.md` |
| Acceptance に速さ・時間・メモリの数字がある | `perf.md` |
| 複数のやり方を試し、どれにするか人間が選ぶ材料を作る | `comparison.md` |
| 画面の見た目・文言・配置・操作が変わる | `ui.md` |
| 調べて設計するだけで、コードを変えない | なし（`型: なし（調査・設計のみ）`） |

例: 「高速 OCR を本番に入れたい（1ページ10秒以内）」は、新しい読み方が増える（feature）と、10秒の数字（perf）の両方。

## 選ぶのは2回

[1] で仮に選んで `型:` に書き、[3] で Acceptance を書き終えたら選び直す。増えた型はファイルを読んでから計画を続ける。

## 型の対応表

型のファイルの見出しの段の項目ごとに1行、計画のどこで満たすか（満たさないなら理由）をミッションの「型の対応表」に書く。型のファイルを開いて書く（記憶で書かない）。

| 型の段 | この計画では |
| --- | --- |
| refactor [3] 消す → 作り替える → 後片付けの順 | やらない。消すものは M-013 に回す（理由: ○○） |

計画レビューの前に `python3 ~/.agents/skills/agent-team/scripts/check_types.py <ミッションファイル>` を流し、止まったら直す。
