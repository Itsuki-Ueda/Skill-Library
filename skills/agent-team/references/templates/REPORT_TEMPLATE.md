# 完了報告の骨組み

[8] の最終報告と status の報告で使う。決めるのは順番と必ず入れるものだけ。言い回し、図や画面写真を使うか、項目の分け方、補足の量は書き手に任せる。
書き方は `~/.agents/docs/writing-policy.md` に従う。

1. 1文目に、人間の判断が必要なものの件数を書く。「判断が必要なものは2件です」「判断が必要なものはありません」。
2. 頼まれたこと1つにつき1行で、結果を言い切る。できた・途中・失敗・未確認のどれか。何が変わったかを、人が使う言葉で書く。
   例: 「19.99 ドルの商品の合計が1セント少なかったのは、価格の読み取りで小数の誤差を切り捨てていたため。読み取りを直し、カートと売上レポートの両方で正しくなりました」
3. 気をつけること（多くても3行）。人間が知らないと困ることだけ。無ければ書かない。
4. 判断待ちを1件ずつ。推奨とその理由、答えなかったらどうなるかを付ける。
   例: 「main に統合してよいか。推奨は統合です。テストと独立レビューが済んでいます。答えが無ければブランチのまま残します」
5. 詳細は最後にまとめる。台帳の1行（`close-mission.sh` の出力）、検証・レビューの達成状況、例外受入・残課題、保持している資源、ブランチ・PR・ミッションファイル。

- 1〜4の本文は、図や表を除いて400字を目安にする。
- コミットのハッシュ、ファイルのパス、テストの件数は、読む人が動くのに要るときだけ本文に書く。それ以外は5に置く。
- 件数・回数・時間は記録で数え直してから書く（原則「数字の出どころを説明する」）。数え直していない値は「自己申告」と書く。
