# 文書ルール（人が読む文章）

最終報告と、README・設計書・PR の説明など人が読む文章を書くときに読む。
エージェント同士の報告（`file:line`・証拠・ラベルが要るもの）には当てはめない。
元は pstack の unslop。英語だけの規則（ダッシュの禁止・英単語の一覧・引用符の形）は外し、日本語で起きる形に直した。

## 中身

1. 仕組みか数字で言う。「使いやすくなった」ではなく「保存が1クリックになった」「12秒が3秒になった」。読む人が何をすればよいか、何が分かるかに言い換えられない文は消す。ほかのプロジェクトの文書にそのまま置ける文は、このプロジェクトについて何も言っていない。
2. 出どころをぼかさない。「一般に〜と言われる」「〜という意見もある」は、出典を書くか消す。
3. 1文に1つのことだけ書く。読み返さないと分からない文は2つに分ける。
4. 主語を書く。「確認されました」ではなく「テストが確かめた」「私が確かめた」。誰がやったか分からないときだけ受け身でよい。
5. 言い切る。「〜の可能性も考えられるかもしれません」のように予防線を重ねない。不確かなら「未確認」と1回だけ書く。
6. 同じものは同じ名前で呼ぶ。言い換えで飾らない。
7. 数を無理に3つにそろえない。あるだけ書く。

## 言葉

8. 決まり文句を書かない。「お役に立てば幸いです」「何かあればお気軽にお知らせください」「素晴らしい質問です」「承知しました！」。
9. 水増しの前置きを消す。「〜することが重要です」「〜という点に留意する必要があります」「〜を行うことで」は、中身だけを書く。
10. 中身の無いカタカナ語を使わない。「シームレス」「包括的」「ロバスト」「エコシステム」「ソリューション」は、具体的な言葉か数字に直す。
11. 比喩でごまかさない。「土台を固める」「北極星」は、実際に何をするのかを書く。
12. 平易な言葉を選ぶ。「活用する」は「使う」、「実施する」は「する」、「〜に関しまして」は「〜は」。
13. 「〜だけでなく〜も」で強調しない。言いたいことをそのまま書く。
14. 副詞で盛らない。「大幅に改善」ではなく、改善した量を書く。
15. 縮めすぎない。矢印・記号・助詞を落とした断片で書かず、普通の文で書く。表の中の短い項目は例外。

## 見た目

16. 太字は、読む人が見落とすと困る箇所だけにする。
17. 絵文字で飾らない。
18. 「**性能:** 性能が上がった」のように、見出しを付けて同じことを繰り返す箇条書きにしない。普通の文にする。
19. 見出し・箇条書き・表は、内容がその形のときだけ使う。3行で済む話に見出しを付けない。

## 締め

20. 一般論で締めない（「今後に期待できます」）。次にやること、決まったこと、未確認のことを書く。
