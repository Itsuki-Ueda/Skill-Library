# 根本原因を直す

不具合は、表に出た場所ではなく、最初に間違えた場所で直す。表に出た場所が「症状」。システムが最初にしてはいけないことをした場所、または扱うべき状態を扱えなかった場所が「根本原因」。

## なぜ

症状だけを直すと証拠が消え、同じ原因が別の場所でまた表に出る。回避策が増えるほど、なぜそう書いてあるのか誰も説明できないコードになる。

## やり方

- まず再現する。
- 「なぜ」を、答えが「前の何かの結果」ではなく「コードの間違った判断」になるまで繰り返す。
- 分からなくなったら推測しない。記録（ログ・print）を足して、実際のエラーと状態を読む。
- 症状を起こした状態が正当かを問う。起きてよい状態なら、そこで壊れたコードが原因で、そこで扱うのが修正。起きてはいけない状態なら、壊れた場所に検査を足すと不具合を隠すだけなので、その状態を作った場所を探す。ガード・再試行・握りつぶした例外・値の切り詰めは、不具合を隠すよくある形。
- 再起動の後にだけ失敗するなら、まず保存された状態（設定・キャッシュ・ロックファイル）を疑う。
- 1か所でなく、同じ間違いの型で探す。同じ間違いをしている場所をすべて直す。共有の関数が原因なら、呼び出し元ではなくその関数を1回直す。
- 回避策の説明に段落が要るなら、コードの方が間違っている。
- 決め手の事実を見つけるのに深く掘る必要があったら、最初から見えていればよかった安い手がかり（ログ・検査）を提案する。

## 飛ばしたと分かる印

修正が症状の出た呼び出し元にだけ入っていて、同じ共有コードを使う他の呼び出し元を調べた記録が無い。
