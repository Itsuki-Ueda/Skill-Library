# 機能地図の雛形

## 目次（`features/README.md`）

```markdown
# 機能地図

| 機能 | ファイル | 流し方の要点 | 実行場所 |
| --- | --- | --- | --- |
| {機能の名前} | `{ファイル名}.md` | {既存スクリプト名 / 手順の一言} | {sandbox / 進行役 / 人間} |

## 未収録
- {地図にまだ入れていない機能・確認スクリプトの名前}

## 確認手段なし
- {機能}: {誰がどう確かめているか}
```

## 機能ごとのファイル（`features/{機能}.md`）

人の目線で書く。4つの見出しは固定。

```markdown
# {機能の名前}

{この機能が何をするかを1〜2文}

## 細かい機能
- {この機能に含まれる操作・表示}

## 入り方（人の目線）
{どこを開き、何を押すとこの機能に着くか}

## 流し方
- 前提づくり: {合成データ・開いた状態。内部の呼び出しを使ってよい}
- 確かめる操作: {人が使うのと同じ入口での操作。既存スクリプトがあれば `{スクリプト}` の `{ブロック・引数}`}
- 完成と言える状態: {見えるもの}＋{保存されたもの（ファイル・DB）}
- 証拠: {撮る画面・残す応答}

## 注意
- {前提が揃わないと流せない部分とその理由}
- {人の画面・本番・秘密の値に触れないための注意}
```
