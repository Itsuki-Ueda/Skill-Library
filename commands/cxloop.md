# /cxloop — Codex レビューゲート（自動ループ）

現在のコード変更を **Codex**（差分レビュー）でレビューし、合格ライン（**P2まで全クリア**）に達するまで
「**Claude が修正 → 再レビュー**」を自動で回す。合格後は**自前ビルドゲート**で green を確認する。
このスキルは**引数解決・手順・合否判定・ループ・ビルドゲート・報告**に専念する。Codex 構文はプロトコルに従う。

## 0. プロトコルを読む（最初に必ず）
- まず `~/.agents/docs/codex-protocol.md` を Read する。
- 以降の Codex 呼び出しはすべてそのプロトコル（`-c` 固定 / stdin / `-o` / session id / timeout / 失敗時 / 履歴）に従う。

## 前提（最初に1度だけ確認）
- `codex --version` が通る。`~/.codex/auth.json` が存在（`codex login` 済み）。無ければ停止して報告。
- カレントが git リポジトリであること（`git rev-parse --show-toplevel`）。

## 引数（`$ARGUMENTS`）
- 空 → 未コミット変更を対象（`review --uncommitted`）
- `base <branch>` → `review --base <branch>`（**worktree 運用では `origin/main` 基準推奨**＝プロトコル 9）
- `commit <sha>` → `review --commit <sha>`
- `model <name>` → モデル上書き（既定はプロトコル §1）
- `effort <level>` → **未指定時は段階制（値はプロトコル §1）。指定時は全ラウンドその値で固定。**
- `max <N>` → **再レビューの上限回数**（初回レビューは含まない。既定 3 ＝計最大 4 回のレビュー）

## 手順

1. **前提チェック**（上記＋プロトコル Read）。NG なら理由を述べて終了。
   引数から対象・model・effort・max を解決。出力用ファイル `<out>`（scratchpad）を決める。

2. **初回レビュー**（プロトコルの**差分レビュー形**、初回 effort＝プロトコル §1）。session id をヘッダから記録、指摘は `<out>` から読む。

3. **合否判定**（重大度の指摘の有無のみで判断）：
   - 差分レビューはタグを課せない（プロトコル 7）。**タグ無し・別語彙（major/minor 等）の指摘が返ったら、
     内容から P0〜P3 を自分で判定する。「タグが無い＝合格」と誤読しない。**
   - P0/P1/P2 相当が **1件でもあれば → 要修正**。
   - 残りが P3 相当のみ、または指摘ゼロ → **Codex レビュー合格（手順 5 へ）**。

4. **要修正なら**：各 P0/P1/P2 指摘に従って **Claude がコードを修正**（Edit/Write）。P3 はついでに直してよいが任意。
   何をどう直したか 1 行ずつ記録。範囲外のファイルは触らない。→ **再レビュー**（プロトコルの**再レビュー形**＝resume、
   effort＝プロトコル §1 の再レビュー値。雛形はプロトコル 8b）→ **手順 3 に戻る**。`max` 回で合格しなければ
   **未解決の指摘を添えて人間にエスカレーション**して終了。

5. **自前ビルドゲート**（Codex レビュー合格後）：
   - プロジェクトのビルドゲートをプロジェクトの CLAUDE.md・package.json から解決して実行し、green を確認する
     （例: `npm run typecheck` / `npm run lint` / `npm run test`）。結果を報告に載せる。
   - red なら修正して green にする。**その修正がロジック変更を伴う場合は、プロトコルの再レビュー形（resume、effort＝プロトコル §1 の再レビュー値）を1回実行し、手順 3 で判定し直す**（この再レビューも `max` のカウントに含める）。
   - **失敗が自分の変更と無関係（ベースで既に落ちている）場合は、勝手に直さずスコープ逸脱として人間に報告**する。

6. **最終報告**：model / effort（ラウンド別）/ session id（各ラウンド）/ ラウンド数 / 最終判定（合格 or
   エスカレーション）/ 各ラウンドの指摘と対処 / 残した P3 / **自前ビルドゲートの結果**。
   session id は必ず示す（後から `codex resume <id>` で辿れるように）。

## 注意
- レビュー自体は読み取り専用。**修正は Claude 側で行う**（Codex に書かせない）。
- これは**コード差分のレビューゲート**。プラン文書のレビューは `/cxplan` を使う。
