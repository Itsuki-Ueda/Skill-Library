# Claude Code 固有設定

## オーケストレーション・プロトコル（モデル条件付き・全プロジェクト適用）
自分のモデルに応じて条件分岐し、役割分担で動く。自分のモデル名は環境情報ブロック（`You are powered by the model named ...`）で毎回確認する。

### 第1層: 調査の委譲 — モデル問わず常時、タスク種別でモデルをルーティング
まとまった調査が必要なときは、読み取り専用サブエージェントに委譲する。モデルはタスク種別で選ぶ（根拠: `tasks/model-comparison-experiment.md`）

- **列挙・棚卸し・存在確認**（ファイル横断スイープ / 命名規約の洗い出し / 使用箇所追跡 / 規模計測）→ `model: "haiku"`
- **意味解釈・再現率が効く調査**（死蔵コード判定 / 重複探索 / セキュリティ調査 / 「まだ使われているか・施行されているか」系）→ `model: "sonnet"`

#### 調査委譲ルール（厳守）
- 調査委譲には `researcher` エージェント定義（`~/.agents/agents/researcher.md`）を必ず使う。
- 定義が使えない場合は同等の規律（証拠必須 / [read][grep][inferred]ラベル / 否定形主張には検索パターン列挙 / コメントと実装の区別 / 末尾に未検証セクション）をプロンプト先頭に付与する。
- 複数エージェントに投げるときは、重要な領域のスコープを意図的に重複させる（矛盾の発生が誤報検出のシグナルになる）。

小さな確認（grep 1回・単一ファイルの一読など）は委譲せず自分でやる（委譲オーバーヘッドの方が大きいため）。

**例外**: `/agent-team` スキル実行中の調査ルーティングは /agent-team 側の設定（defaults.yaml）に従う
（既定はCodexの `team-researcher` へ委譲。CC researcherは人間のCC指定時とCodex制限時のフォールバック）。
スコープ重複の工夫と第1.5層の検証プロトコルは、委譲先を問わずそのまま適用する。

### 第1.5層: 調査出力の検証プロトコル（全モデル共通・機械的に適用）
受領した報告には誤報が紛れている可能性を考慮し、以下を**解釈を挟まず機械的に**適用する:

1. 証拠（`file:line` + 逐語引用）のない主張は破棄する。
2. 次のいずれかに該当する主張は、採用前に自分で grep/Read で裏取りする:
   - (a) 判断や成果物の内容を左右する
   - (b) プロジェクトメモリ・CLAUDE.md と矛盾する
   - (c) 否定形（「存在しない」「未使用」「参照ゼロ」）
   - (d) `[grep]` ラベル付きで、コメントか実装かの区別が結論に効く
3. 具体的な数値は精緻でない場合がある。文書に確定値として書く前に自分で再計測する。
4. 複数の報告間で矛盾する主張は、必ず裏取りしてから採用する（スコープ重複は第1層で仕込んでおく）。

### 第2層: 実装委譲を含むフル・オーケストレーション — 自分が Fable のときだけ
自分が **Fable** の場合のみ発動:
- Fable（自分）: 計画立案・レビュー・全判断・デバッグの原因判断と方針決定に専念。**実装の手は動かさない**。
- 実装は `coding-agent` エージェント定義（`~/.agents/agents/coding-agent.md`、model: opus。完了条件・スコープ規律・エスカレーション条件は定義側に記載）に仕様書を渡して委譲する。定義が使えない場合は同等の規律（ビルド・テスト通過が完了条件 / 一次デバッグは実装側 / 2回失敗・設計波及・複数モジュール横断でエスカレーション）をプロンプトに付与して `model: "opus"` で委譲する。
- レビューは Fable が diff を直読。差し戻しは**同じエージェントに SendMessage で追加指示**を送り、合格までループ（文脈を保持したまま継続）。

自分が **Fable 以外**（Opus / Sonnet / Haiku 等）の場合: フル・オーケストレーションは発動せず、実装・レビュー・判断は自分でやる。ただし第1層（まとまった調査の Haiku・Sonnet 委譲）は引き続き適用する。

| メインの自分 | 調査 | 実装 | レビュー/判断 |
|---|---|---|---|
| Fable | investigator(Haiku/Sonnet) に委譲（第1層の種別ルーティング） | coding-agent(Opus) に委譲 | Fable（自分） |
| Opus | investigator(Haiku/Sonnet) に委譲（同上） | 自分でやる | 自分でやる |
| Sonnet/Haiku 等 | investigator(Haiku/Sonnet) に委譲（同上） | 自分でやる | 自分でやる |

注: thinking レベル（high 等）を API で直接指定する手段はない。深い思考が要るときはプロンプトで促す。
