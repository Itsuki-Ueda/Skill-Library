# 小さく確かめながら積む

作業を、終わるたびに確かめられる小さな単位の列にし、今の単位が通るまで次へ進まない。

## なぜ

壊れたのを壊した単位で見つければ、場所はすぐ分かる。まとめて作ってから見つけると埋もれていて、しかも壊れた土台の上にもう積んでしまっている。

## やり方

- 似た編集を続けるときは、1つ変えるごとに確かめてから次へ進む（正常な状態 → 1つ変える → 確かめる → 次へ）。道具で編集するなら確認はほぼ無料なので、それでも毎回流す。
- 始める前に、比べる基準（今のテストが通るか、今の数字はいくつか）を取っておく。
- コミットの順番で、作業が正しいことを示す。基本の形は「失敗するテストのコミットの上に、それを通す修正のコミット」。ほかに、作り替えの前に消す、手を入れる前に基準を測る、機能の前に土台を置く、がある。落ちてよいのは、失敗を示すために分けたテストのコミットだけで、ほかのコミットは単独で通る。テストと修正を1つのコミットにする流れ（agent-team の task commit など）では、修正の前にテストが落ちることを流して記録しておく。

## 飛ばしたと分かる印

最後に一度だけテストを流し、どの変更で壊れたか分からない失敗を調べている。
