# 本物で確かめる

作業の結果は、本物を直接見て確かめる。代わりの手がかり（ファイルの更新時刻、担当者の自己申告、「ビルドが通った」）から推し量らない。

## なぜ

確かめていない結果は、正しいかどうか分からない。手がかりから推すほうが安く見えるが、外れたときの手戻りのほうがずっと高い。

## やり方

- プロセスが動いているかは、プロセスそのものを見る。値は、キャッシュや画面の表示ではなく元の値を読む。
- 確かめられなかったものは「未実行: 理由」と書く。実行の記録が無い合格は報告しない。
- 確かめ方が失敗したら、対象より先に確かめ方を疑う。
- できるなら確認をスクリプトにする。誰でも同じ比較を流し直せる形にし、その出力を証拠として残す。

## 飛ばしたと分かる印

報告に「通った」「動いた」とあるのに、実行したコマンド・終了コード・見た出力のどれも付いていない。
